# Как внести вклад в THEDAD

Спасибо, что хотите помочь! Этот документ описывает процесс.

## Соглашение о лицензировании

THEDAD использует модель open-core (ядро под AGPL-3.0). Отправляя pull request,
вы соглашаетесь, что ваш вклад в ядро публикуется под **AGPL-3.0-or-later** и
может также распространяться мейнтейнерами под коммерческой лицензией для
Pro-функций (inbound = AGPL, dual-license by maintainers). Если вы не согласны —
не отправляйте PR в этот репозиторий.

## С чего начать

1. Найдите или заведите issue с описанием задачи.
2. Форкните репозиторий, создайте ветку: `feat/<кратко>` или `fix/<кратко>`.
3. Установите зависимости: `bun install`.
4. Запустите dev: `bun run dev`.

## Перед коммитом

```bash
bun run lint      # tsc --noEmit — должен пройти без ошибок
bun run build     # прод-сборка должна собираться
```

- TypeScript в **strict**-режиме. Любой `any` — только с обоснованием.
- Следуйте существующему стилю кода (отступы, нейминг, структура).
- Бизнес-логика — в `src/lib/`, без зависимости от React.
- UI — в `src/components/` и `src/pages/`.
- Не коммитьте `node_modules/`, `dist/`, `.vite/`.

## Стиль коммитов

Conventional Commits:

```
feat: добавил radar-график баланса
fix: чекбокс цели больше не открывает переход
docs: обновил README
refactor: вынес прогноз в lib/forecast.ts
```

## Pull request

- Один PR — одна логическая фича/исправление.
- Опишите **что** и **зачем**. Приложите скриншот для UI-изменений.
- Убедитесь, что `bun run lint` и `bun run build` проходят.
- PR должен быть основан на актуальном `main`.

## Дизайн-принципы

- **Local-first**: никаких сетевых запросов с пользовательскими данными в ядре.
- **Приватность**: данные не покидают устройство.
- **Реактивность < 100 мс**: тяжёлые вычисления — мемоизировать.
- **Минимализм UI**: одна задача на компонент, без визуального шума.
