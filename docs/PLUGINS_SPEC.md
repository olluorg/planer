# THEDAD — плагины (виджеты/страницы): спецификация

Статус: **уровень A реализован** (2026-07-11): `src/lib/plugins.ts` (валидация + read-only выборка),
рендер `src/components/dashboard/PluginWidget.tsx`, импорт/экспорт/удаление в Настройки → Плагины
и в окне «Добавить виджет» дашборда. Хранение — `localStorage` (`plugins.installed.v1`), как и
остальное UI-состояние (раскладка, скрытые виджеты). Примеры — `docs/plugins/*.thedad-widget.json`.
Уровень B (sandbox-iframe) — не реализован.

Расширение (2026-07-12): контентные плагины — `source.static` (записи прямо в файле, до 500)
и `render.type: "cards"` (карточки: картинка + описание, по клику текст-«рецепт», `dayField`
листает набор по дню месяца). Картинки — только локальные пути (`/food/…`), внешние URL
отклоняются при импорте (анти-трекинг). Гайд для пользователей — `docs/plugins/GUIDE.md`,
пример — `nutrition-month.thedad-widget.json`. Примеры продублированы в `public/plugins/`
(заготовка под «Каталог» из статики, п. 3.5).

## 1. Зачем

Дашборд стал сеткой виджетов, а навигация — раскрытием виджета в страницу (модалка почти
на весь экран). Логичный следующий шаг — дать пользователю **добавлять свои виджеты-страницы**
и импортировать чужие. Цель: экосистема расширений вокруг local-first ядра, без сервера.

## 2. Железное ограничение: безопасность

THEDAD — **local-first**: все данные (цели, здоровье, рефлексия, AI-ключ) лежат в IndexedDB
на устройстве. Импортированный плагин с **произвольным JS** = прямой вектор кражи: он сможет
прочитать весь стор и AI-ключ и отправить их на любой адрес. Прошлый security-аудит (перед бетой)
специально закрывал XSS. Поэтому произвольный JS из импорта **по умолчанию запрещён**.

Три уровня доверия, по возрастанию риска:

| Уровень | Что это | Риск | Когда |
|---|---|---|---|
| **A. Декларативный** | JSON-описание: данные из стора + тип отображения | нет исполнения кода | **MVP, старт отсюда** |
| **B. Sandbox-iframe** | HTML/JS плагина в `<iframe sandbox>` с postMessage-API | изолирован от стора и сети | фаза 2 |
| **C. Нативный** | код собран в бандл приложения | полный доступ | только официальные виджеты |

Данный документ детально описывает **уровень A** (то, что строим первым) и намечает **B**.

## 3. Уровень A — декларативный плагин (MVP)

Плагин — это **`.thedad-widget.json`** файл, который пользователь импортирует через
Настройки → Плагины → «Импортировать». Никакого исполняемого кода.

### 3.1 Формат

```jsonc
{
  "schema": "thedad.widget/v1",
  "id": "streak-heatmap",           // уникальный slug
  "name": "Тепловая карта серий",
  "author": "user или @nick",
  "icon": "flame",                   // имя lucide-иконки из белого списка
  "defaultSize": { "w": 4, "h": 5 }, // в единицах grid (12 колонок)
  "source": {                        // ОТКУДА данные — только из стора, read-only
    "collection": "habitLogs",       // одно из разрешённых (см. 3.2)
    "range": "last-30-days",         // предопределённые окна, не произвольный код
    "groupBy": "date"
  },
  "render": {                        // КАК показать — фиксированный набор примитивов
    "type": "heatmap",               // stat | list | bar | line | ring | heatmap | table
    "value": "count",
    "label": "{{date}}"
  }
}
```

Никаких выражений/JS в полях — только **имена полей** и значения из белых списков.
Подстановка `{{field}}` — простая замена по ключам записи, без eval.

### 3.2 Разрешённые источники данных (read-only)

Плагин видит только эти коллекции стора, через тонкий read-only адаптер `pluginDataApi`:

`goals`, `tasks`, `habits`, `habitLogs`, `healthLogs`, `progress`, `reflections`, `timeEntries`.

**Не отдаём** плагину: AI-ключ, конфиг синка, ключи шифрования, `localStorage` целиком.
Адаптер отдаёт **копии** записей (structuredClone), плагин не может мутировать стор в MVP
(запись — только через явные экшены пользователя, не через плагин; см. фаза 2).

### 3.3 Типы отображения (`render.type`)

Переиспользуем уже существующие примитивы приложения — новых движков не пишем:
`stat` (число+подпись), `list`, `bar`/`line` (ECharts-обёртка с renderMode:'richText'),
`ring` (ui/ring), `heatmap` (как WeeklyConsistency), `table`. Каждый тип валидирует свой набор
полей; неизвестный тип → плагин отклоняется при импорте.

### 3.4 Импорт / хранение / жизненный цикл

- Импорт: файл-пикер → **валидация по JSON-схеме** (`schema: thedad.widget/v1`) → при ошибке
  показываем что не так, не устанавливаем.
- Хранение: список установленных плагинов в IndexedDB (`plugins.installed.v1`), НЕ в бандле.
- Появление: установленный плагин доступен в редакторе раскладки дашборда как обычный скрытый
  виджет (Dashboard `DEFAULT_HIDDEN` + реестр). Пользователь сам добавляет его на сетку.
- Удаление/выключение: из Настройки → Плагины.
- Экспорт: любой пользовательский плагин можно выгрузить обратно в `.json` (шаринг без сервера).

### 3.5 Реестр (позже)

Опционально — курируемый список готовых `.json`-виджетов в репозитории (`/plugins/*.json`),
кнопка «Каталог» в Настройках подтягивает их из статики. Без исполняемого кода — безопасно.

## 4. Уровень B — sandbox-iframe (фаза 2, эскиз)

Для плагинов, которым мало декларативного: HTML/JS плагина рендерится в
`<iframe sandbox="allow-scripts">` (без `allow-same-origin` → нет доступа к родительскому DOM,
куки, IndexedDB, localStorage). Общение — только через `postMessage`:

- плагин → хост: `{type:'query', collection, range}` → хост отвечает копией данных (те же белые
  списки, что в 3.2);
- хост → плагин: `{type:'data', ...}`, `{type:'theme', ...}`.
- сеть плагина глушится CSP на iframe (`connect-src 'none'`), чтобы не было эксфильтрации.

Запись в стор — только через `{type:'action', name:'addTask', payload}` с **явным подтверждением
пользователя** на стороне хоста (плагин не пишет молча).

## 5. Что НЕ делаем (анти-цели)

- Произвольный `<script>`/eval из импорта — никогда на уровне A.
- Доступ плагина к AI-ключу, синку, шифрованию.
- Сетевые запросы плагина к произвольным адресам (эксфильтрация).
- Автозапуск/автообновление плагинов из сети без действия пользователя.

## 6. План внедрения

1. **Спека утверждена** (этот файл).
2. `lib/plugins.ts`: типы, JSON-схема-валидатор, `pluginDataApi` (read-only адаптер к стору).
3. Реестр установленных + интеграция в Dashboard-редактор (виджет из плагина = ячейка сетки).
4. Настройки → Плагины: импорт/экспорт/список/удаление.
5. 2–3 эталонных `.json`-виджета как примеры и тест.
6. (Позже) уровень B — iframe-sandbox.
