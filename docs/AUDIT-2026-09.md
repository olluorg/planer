# Аудит перед релизом 1.0 и идеи развития

Сентябрь 2026. Второй проход после «release hardening». Всё, что помечено
«исправлено», подтверждено тестом или замером, а не на глаз.

## Итог одной строкой

Приложение готово к выпуску с технической стороны. Препятствия остались только
организационные (лицензия, ссылки на покупку, аккаунты) — они в
[`DEPLOY.md`](../DEPLOY.md). Перед включением Plus обязательно одно: слияние
изменений в синхронизации вместо «побеждает последний».

## Что найдено и исправлено в этом проходе

### Критичное — данные и первое впечатление

| Проблема | Как проявлялась | Доказательство |
|---|---|---|
| **Потеря свежих правок** | Отметка, сделанная за ¼ секунды до закрытия вкладки или обновления, пропадала. Прежняя «защита» (flush на pagehide) не работала: запись в IndexedDB обрывается вместе с документом | Замер: задержка 0 и 150 мс — потеряно, 400 мс — сохранено. После исправления 12/12, включая мгновенную перезагрузку |
| **Перезагрузка у каждого нового пользователя** | Через секунду после первого открытия страница перезагружалась сама — посреди мастера. Service worker при первой активации меняет контроллер, обработчик воспринимал это как обновление | Регрессионный тест падает без исправления, проходит с ним |
| **Сайт пропал бы при закрытии кода** | Pages на бесплатном плане — только для публичных репозиториев. Перевод `planer` в приватный выключил бы thedad.ru | Сайт теперь публикуется в `gh-pages` публичного `thedad-releases`; карт исходников в сборке нет |
| **Прямые ссылки на Pages → 404** | Открыть `thedad.ru/goals` по ссылке или обновить страницу — страница ошибки GitHub | В сборке `404.html` = приложение; тест |

### Безопасность

| Проблема | Исправление |
|---|---|
| Нет CSP ни в вебе, ни в десктопе — любая XSS получала полный доступ к базе | Политика мета-тегом в сборке. Проверено на 13 экранах: Google Identity и YouTube работают, чужой скрипт и инлайн-инъекция блокируются |
| Окно Electron с мостом в main-процесс могло уйти на чужой сайт | `will-navigate` пускает только своё приложение; из разрешений — уведомления, геолокация, буфер обмена; песочница явно |
| В сборку расширения уезжал сырой `__APP_VERSION__` — «Скопировать отчёт» падал | Общие части конфигов в `vite.shared.ts` |

### Sync-сервер (найдено при прогоне в Docker)

| Проблема | Последствие |
|---|---|
| Необработанное `error` пула Postgres | Любой перезапуск базы ронял сервер в цикл перезапусков. Теперь живёт, отвечает 503, восстанавливается сам |
| Страховочный бэкап с тем же именем, что исходный дамп | Восстановление **затирало хорошую копию** испорченным состоянием. Воспроизведено: после «аварии» единственный файл содержал 0 хранилищ |
| CRLF в `.env` из Windows | Невидимый `\r` в пароле шифрования — зашифрованную копию нельзя восстановить |
| `sudo update.sh` запускал git от root | «dubious ownership» и нет ключа доступа — обновление не работало бы |
| Нет исполняемых битов в git | На сервере «Permission denied» на первом же шаге |

### Доступность и скорость

- **Доступность:** 3 `aria-label` на 359 кнопок. Галочки задач читались как
  «флажок» без названия задачи. Найдено 16 видов безымянных элементов, все
  исправлены; постоянный тест держит ноль.
- **Скорость:** 1717 КБ JavaScript до первой отрисовки, из них 616 КБ —
  библиотека графиков. Стала ленивой: **1103 КБ, −36%**.

## Что осталось — по приоритету

### P0 — до выпуска (решения владельца)

- **Лицензия.** AGPL при закрытом коде — ложное обещание пользователям.
- **`buyUrl` = `CHANGE_ME`** — кнопка покупки программ ведёт в никуда.
- **Подпись кода Windows** — без неё SmartScreen у каждого пользователя.

### P1 — до включения Plus

- **Синхронизация «побеждает последний».** Правка на телефоне, сделанная пока
  ноутбук был офлайн, молча затирается при следующем синке с ноутбука. Для
  платной функции это недопустимо. Нужно слияние по записям: `updated_at` на
  каждой строке, надгробия для удалений, слияние на клиенте (сервер видит
  только шифр и слить не может). Оценка: 1–2 недели.
- **152-ФЗ.** Сервер хранит e-mail — уведомление в Роскомнадзор, политика
  обработки ПДн, база в РФ. См. `deploy/server/README.md`.
- **Тесты модулей, где ошибка стоит денег или данных:** `sync.ts` (0 тестов),
  проверка лицензий в `marketplace.ts` (0 тестов — подпись Ed25519 проверяется
  правильно, но это нигде не зафиксировано), `store.ts` — 662 строки ядра CRUD
  покрыты только e2e.

### P2 — после релиза

- **Цена записи.** Теперь каждое действие экспортирует всю базу целиком
  (`db.export()`). При нынешних ~200 КБ это миллисекунды; при 5+ МБ начнутся
  подтормаживания. Мерить на реальных пользователях; решение — запись раз в
  N действий плюс надёжный flush, либо переход на OPFS с построчной записью.
- **Лицензии программ не привязаны к человеку** — ключ можно переслать.
  Для 299 ₽ это приемлемо; при дорогих курсах — привязка к аккаунту Plus.
- **Мастер первого запуска — 9 шагов.** До первой цели — долго. Сократить до
  трёх: имя → одна цель числом → первая отметка.
- **Копия в Google Диск недоступна в расширении** (CSP расширения не пускает
  Google Identity). Решение — `chrome.identity.launchWebAuthFlow`.
- **Напоминания в браузере — только при открытой вкладке.** Десктоп и
  расширение умеют; для веба нужен push-сервер (VAPID) или Telegram (ниже).
- **Главный чанк 452 КБ и vendor 379 КБ.** Следующий шаг — ленивые виджеты
  дашборда.

### P3 — гигиена

- Архивировать `planer-desktop`, удалить локально (2 ГБ).
- `src/graphify-out/` лежит внутри исходников — вынести к корневому.

## Идеи развития

Принцип прежний: не расширяться вширь. Каждая идея либо усиливает то, что
отличает приложение (прогноз), либо прямо помогает продавать, либо снимает
причину уйти. Оценка: S — дни, M — неделя-две, L — больше.

### Усилить главное — прогноз

**1. Предупреждение «не успеваете» — S.**
Сейчас прогноз пассивен: его надо открыть. Когда дата достижения уходит за
срок, в уведомления приходит одна карточка с тремя честными выходами: поднять
темп (на сколько — уже считается), сдвинуть срок (на когда), уменьшить цель
(до скольки). Всё нужное есть: `forecast.ts`, `inbox.ts`. Самая дешёвая фича с
самым прямым эффектом на удержание.

**2. Недельный обзор — M.**
Пять минут в воскресенье по шагам: по каждой цели факт против прогноза, что
сорвалось и почему (из рефлексий), что перенести, план на неделю. Превращает
приложение из «трекера» в ритуал, к которому возвращаются. Основа есть:
`weekly.ts`, `report.ts`.

### Снять трение

**3. Быстрый ввод отовсюду — S.**
Десктоп: глобальная клавиша (`globalShortcut`) открывает маленькое окно
записи поверх любого приложения. Расширение: ключевое слово в адресной строке
(`td купить молоко`). Задача записывается за две секунды, не открывая планер.

**4. Импорт из Todoist, TickTick, Google Tasks — S–M.**
Главная причина не переходить — «у меня там всё». CSV/JSON-экспорт у всех
троих есть; парсер CSV в приложении уже есть.

**5. Android в Google Play и RuStore — S–M.**
PWA упаковывается в APK через TWA (Bubblewrap) без переписывания. RuStore
принимает такие APK — отдельный канал для российской аудитории.

### Plus — за что платят

**6. Синхронизация со слиянием — L** (см. P1). Без неё Plus продавать нельзя.

**7. AI-коуч без своего ключа — M.**
Прокси на том же сервере, квота на пользователя, провайдер на ваш выбор.
Сейчас AI требует у человека ключ OpenAI — для большинства это стена.

**8. Напоминания в Telegram — M.**
Для телефона без нативного приложения это ответ на «напоминания не приходят».
Бот на том же сервере. Компромисс, который нужно честно показать: текст
напоминания проходит через сервер и Telegram — функция только по согласию.

**9. Партнёр по цели — M.**
Ссылка «только чтение» на прогресс одной цели для друга или тренера. Ключ —
в `#хеше` ссылки, как у QR-привязки: сервер видит только шифр. Даёт
органический рост без соцсети.

### Чего не делать

Команды и общие проекты, чаты, лента, интеграции с Jira и Slack, «семейный»
режим. Каждое из этого — путь в суперапп и в конкуренцию с теми, у кого на
порядок больше ресурсов.
