# Маркетплейс премиум-программ

Монетизация без сервера: премиум-«Программы» (многонедельные курсы — питание +
тренировки + цели + привычки + задачи по дням) продаются как зашифрованные паки.
Оплата — на внешней странице, доставка — лиценз-ключом с Ed25519-подписью.

## Как это работает

1. **Витрина** — `public/marketplace/catalog.json` (открытая, only-превью). Точки входа
   в приложении: плитка 🛒 в «Добавить виджет» и кнопка на странице «Шаблоны»
   (событие `thedad:marketplace`).
2. **Оплата** — кнопка «Купить» ведёт на `buyUrl` (Boosty / ЮKassa / …). Платформа
   отдаёт покупателю лиценз-ключ (ты генеришь его после оплаты, см. ниже).
3. **Активация** — «Есть ключ» → вставить `THEDAD-…`. Приложение проверяет подпись
   встроенным публичным ключом (`MARKETPLACE_PUBLIC_KEY` в `src/lib/marketplace.ts`),
   сохраняет ключ расшифровки в localStorage.
4. **Установка** — «Установить» скачивает `/marketplace/<id>.pack`, расшифровывает
   (AES-256-GCM) и разворачивает в цели/привычки/задачи/виджет. Всё локально.

Защита «лёгкая» (как чек на ebook): ключ можно переслать, но копирование `.pack`
без ключа бесполезно. Идеальной защиты в local-first нет — это осознанный компромисс.

## Разовая настройка

```bash
node scripts/gen-keypair.mjs
```
Создаёт `secrets/signing-key.json` (приватный — НЕ коммитить, уже в .gitignore) и печатает
публичный ключ. Вставь его в `src/lib/marketplace.ts → MARKETPLACE_PUBLIC_KEY`.

## Что делает пак «премиумом» (не повторить бесплатным AI)

Данные (цели/задачи) — не ценность, их генерит и бесплатный AI. Премиум — это:

- **Программа-плеер** (`days[]`) — направляемый режим «День X из N»: урок дня,
  тренировка с упражнениями, меню с рецептами, акцент на привычках, прогресс.
  Компонент `ProgramRunner.tsx`, открывается кнопкой «Открыть» после установки.
- **Курированная медиа** (гибрид):
  - **фото блюд/упражнений** — поле `photo`, вшивается в пак как `data:image/...`
    (приватно: без покупки не скачать, т.к. пак зашифрован). Локальные пути тоже
    допустимы, но они публичны — для премиума используй dataURL.
  - **видео-демо** — поле `video`, только YouTube (id или ссылка). Открывается
    ссылкой (внешние превью не грузим — приватность).

Формат дня: `{ day, title, lesson, workout{title,note,video,exercises[]},
meals[{meal,title,kcal,photo,recipe,video}], focusHabits[] }`. `duration_days` —
длина курса. `getProgress`/`currentDay`/`toggleDayDone` в `marketplace.ts` считают
«День X из N» от даты установки.

- **Фитнес-хаб** (`WorkoutHub.tsx`, поле `hub` в паке) — кинематографичный экран
  занятий спортом (см. `exampe.jpg`): герой + хедлайн, цели-чеклист (сохраняются в
  localStorage), стрик тренировок (считается из `healthLogs` metric 'workout'),
  недельное расписание по типам и библиотека сессий (фото/тип/длительность/видео +
  упражнения). «Завершить тренировку» → `logWorkout` → активность/стрик/цели двигаются.
  Открывается по `openWorkoutHub(id)`; в каталоге `kind:'hub'` делает кнопку «Открыть»
  входом в зал, а не в плеер. Типы: `WorkoutHub{hero,headline,quote,goals[],sessions[],
  schedule[]}`, `WorkoutSession{id,title,type,duration,photo,video,note,exercises[]}`,
  `HubScheduleDay{label,sessions[]}` (sessions ссылаются на id). Цвета типов —
  strength/cardio/yoga/calisthenics/mobility.
- **Адаптивная логика** (`programAdapt.ts`, `analyzeProgram`) — движок читает
  РЕАЛЬНЫЕ `healthLogs` пользователя во времени (вес/тренировки/калории) и выдаёт
  подстройку: отстаёшь от графика → ужесточить дефицит; теряешь слишком быстро →
  добавить калорий; пропускаешь тренировки → наверстать; идёшь в графике → прогрессия.
  Показывается баннером «Подстройка под тебя» в плеере. Это принципиально не
  повторить одним AI-промптом — нужна связь с данными во времени. Целевой темп берётся
  из цели пака с unit «кг» и `duration_days` (иначе 0.5 кг/нед).

> Фото в примере `weight-loss-8w.json` пустые (эмодзи-заглушки). Перед продажей
> вставь реальные сжатые dataURL в поля `photo` и id роликов в `video`, затем
> перешифруй пак (ключ пака сохранится — уже выданные лицензии продолжат работать).

## Добавить новую программу

1. Написать контент: `content/programs/<id>.json` (schema `thedad.program/v1`,
   поле `id` == имя файла-slug). Пример — `content/programs/weight-loss-8w.json`.
   Наполни `days[]` уроками, тренировками и меню (это и есть премиум-опыт).
2. Зашифровать:
   ```bash
   node scripts/pack-encrypt.mjs content/programs/<id>.json <id>
   ```
   → `public/marketplace/<id>.pack` + ключ пака в `secrets/pack-keys.json`.
3. Добавить карточку в `public/marketplace/catalog.json` (title, price, buyUrl, includes,
   опционально `preview` → положить картинку в `public/marketplace/preview/<id>.jpg`).

## Выдать ключ покупателю (после оплаты)

```bash
node scripts/gen-license.mjs <id[,id2]> [email-или-имя-покупателя]
```
Печатает `THEDAD-…` — его отдаёшь покупателю. Один ключ может открывать несколько паков.

## Что коммитить, а что нет

| Коммитить | НЕ коммитить (в `secrets/`) |
|-----------|------------------------------|
| `public/marketplace/*.pack` (зашифровано) | `secrets/signing-key.json` (приватный ключ) |
| `public/marketplace/catalog.json` | `secrets/pack-keys.json` (ключи расшифровки) |
| `content/programs/*.json` (исходники) | — |
| публичный ключ в `marketplace.ts` | — |

> ⚠️ Потеря `secrets/` = невозможность выдавать новые ключи к уже проданным пакам
> (у купивших всё продолжит работать). Храни бэкап `secrets/` в надёжном месте.
