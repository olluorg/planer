# THEDAD — дорожная карта экосистемы

Переход от веб-приложения/расширения к экосистеме: телефон, умные часы, синхронизация
с сервисами здоровья и еды. Документ — план и архитектурные решения, а не готовый код.

Главный принцип сохраняется: **local-first**. Данные живут на устройстве; облако — только
опциональный E2E-зашифрованный транспорт между своими устройствами, не «сервер-владелец».

## 0. Что уже есть (фундамент)

- **Единый слой метрик** `healthLogs` и централизованная синхронизация `useHealthSync`
  (см. [DATA_FLOW.md](./DATA_FLOW.md)). Любой источник, пишущий в `healthLogs`, сразу
  виден во всех виджетах и целях — это и есть точка входа для внешних интеграций.
- **Синхронизация устройств** — `lib/sync.ts`: аккаунт (email+пароль), зашифрованное
  хранилище (vault), `pushNow` / `pullNow` / `syncNow`, привязка по ссылке/QR
  (`buildSyncLink`, `importSyncFromHashIfPresent`). Это транспорт для мультиустройства.
- **PWA-манифест** (`site.webmanifest`, `display: standalone`) и **service worker**
  (`public/sw.js`) — заготовка под установку на телефон.
- **Плагины** (`docs/PLUGINS_SPEC.md`) — расширяемость контента без кода.

## 2. Фаза B — нативная обёртка (Capacitor)

Оборачиваем ту же веб-сборку в нативный контейнер — доступ к системным API здоровья.

- [ ] **Capacitor** (`@capacitor/core` + `ios`/`android`). Веб-ассеты — из текущего Vite-билда.
- [ ] Плагины: локальные уведомления (заменяют heartbeat), фон, шаринг, файловая система
      (экспорт .sqlite/.json), биометрия для разблокировки vault.
- [ ] Сборки в App Store / Google Play (или Play Internal / TestFlight на старте).

Альтернатива: React Native (переписывание UI) — дороже; Capacitor переиспользует весь UI.

## 3. Фаза C — интеграции здоровья (носимые и телефон)

Все провайдеры реализуют **один контракт** и пишут в `healthLogs` — дальше работает то,
что уже есть (виджеты, баланс, цели). Предлагаемый интерфейс:

```ts
// lib/health/provider.ts (эскиз)
export interface HealthSample { date: string; value: number }
export interface HealthProvider {
  id: 'manual' | 'apple-health' | 'health-connect' | 'google-fit';
  label: string;
  isAvailable(): Promise<boolean>;
  requestPermissions(metrics: HealthMetric[]): Promise<boolean>;
  read(metric: HealthMetric, from: string, to: string): Promise<HealthSample[]>;
  // запись — опционально (например, вес/тренировку обратно в Health)
  write?(metric: HealthMetric, sample: HealthSample): Promise<void>;
}
```

Конкретные провайдеры (через Capacitor-плагины):

| Провайдер | Платформа | Метрики | Механизм |
|---|---|---|---|
| **Apple HealthKit** | iOS + Apple Watch | шаги, вес, тренировки, сон, энергия, пульс | `capacitor-health` / нативный мост |
| **Android Health Connect** | Android + Wear OS | те же | Health Connect SDK |
| **Google Fit** | Android (legacy) | шаги, активность | Fitness REST (уходит в пользу Health Connect) |
| **Manual** | всё | что угодно | текущий ручной ввод (уже есть) |

Поток: провайдер читает нативные данные → маппит в `HealthMetric` → `upsertHealthLog`.
Реестр активного провайдера — в настройках («Источник данных здоровья»). Пользователь
явно выдаёт разрешения (privacy-first). Синхронизация — по расписанию/при открытии.

## 4. Фаза D — сервисы еды

Ускорить ввод продуктов и БЖУ (сейчас — только вручную в «Мои продукты»).

- [ ] **Open Food Facts** — открытая база, без ключа: скан штрих-кода камерой
      (`@capacitor/barcode-scanner`) → продукт + БЖУ/ккал → в «Мои продукты».
- [ ] Кеш ответов локально (offline-first). Запросы — только по явному действию
      пользователя (скан), не в фоне — согласуется с анти-эксфильтрацией.
- [ ] Опционально: USDA FoodData Central (ключ), локальные базы рецептов как плагины.

Важно: внешние запросы — **first-party и по действию пользователя**; плагинам сеть
по-прежнему запрещена (см. PLUGINS_SPEC §5).

## 6. Порядок и оценка

1. Фаза A (PWA) — дни. Даёт «мобильное приложение» без сторов уже сейчас.
2. Фаза B (Capacitor) — 1–2 недели. Открывает системные API.
3. Фаза C (HealthKit/Health Connect) — по провайдеру; сначала iOS+Watch (HealthKit).
4. Фаза D (Open Food Facts + сканер) — параллельно C, независимо.
5. Фаза E (фоновый синк, часы) — после стабилизации C/D.

## Анти-цели

- Не превращать local-first в «сервер-владелец»: облако остаётся опциональным E2E-транспортом.
- Не давать плагинам доступ к сети и системным данным здоровья.
- Не собирать телеметрию/аналитику пользователя.
