# THEDAD Sync Server

Синхронизация зашифрованных на клиенте дампов базы. Гарантии различаются для
входа по email и привязки без аккаунта; см. раздел ниже.

## Запуск (Docker)

```bash
cd server
docker compose up --build
# сервер на http://localhost:8787, Postgres в томе thedad_db
```

## Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | проверка живости |
| POST | `/vault` | создать анонимный vault (для QR-привязки) → `{syncId, authToken}` |
| POST | `/register` | `{email, password, salt}` → `{syncId, authToken, salt}` |
| POST | `/login` | `{email, password}` → `{syncId, authToken, salt}` |
| PUT | `/vault/:id` | (Bearer authToken) `{ciphertext, updatedAt, expectedRevision}` — атомарно записать блоб; 409 при изменившейся версии |
| GET | `/vault/:id` | (Bearer authToken) → `{ciphertext, updatedAt, revision}` |

При обновлении сервер добавляет столбец `revision` к существующей базе. Сервер
отклоняет старые клиенты без версии (HTTP 426), а новый клиент отказывается
писать на старый сервер. Обновляйте сервер и приложения согласованно; до
обновления всех устройств синхронизация на старых версиях будет недоступна.
Перед обновлением сохраните резервную копию базы сервера.

Тела запросов регистрации и входа ограничены 16 КиБ и требуют строковые
пароль и, при регистрации, соль. Ограничение не относится к зашифрованному
дампу в `PUT /vault/:id`, для которого сохраняется лимит 60 МиБ.

Клиент принимает HTTP только для loopback-адресов текущего устройства; для
удалённого сервера требуется HTTPS. Уже настроенное подключение можно перевести
на HTTPS в настройках: приложение проверяет доступ к хранилищу и, если в нём
есть данные, ключ, не стирая прежнюю конфигурацию при ошибке. Изменение адреса
не переносит базу.

## Шифрование и ограничения

- Клиент шифрует дамп SQLite ключом `encKey` (AES-GCM) **до** отправки.
- Для email-входа `encKey` выводится из пароля через PBKDF2(password, salt) на клиенте. При регистрации и входе пароль передаётся серверу, который хранит `salt` и `pass_hash`. Сервер технически может вывести `encKey` из полученного пароля и соли: защита от оператора сервера этим режимом не гарантируется. Используйте HTTPS и доверенный сервер.
- Для QR-привязки `encKey` случайный и передаётся в QR (в URL-хеше), на сервер не попадает.
- Сервер хранит шифртекст, метаданные и учётные данные, описанные выше. По QR ключ также присутствует в ссылке и доступен тому, кто её получил.

## Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `DATABASE_URL` | локальный Postgres | подключение к БД |
| `PORT` | `8787` | порт |
| `ALLOWED_ORIGINS` | пусто (любой источник) | список доменов через запятую. **В проде задавать обязательно** — иначе чужая страница сможет обращаться к API от имени залогиненного пользователя |
| `RATE_LIMIT_MAX` | `120` | запросов в минуту с одного IP |
| `TRUST_PROXY_CIDRS` | пусто | IP-адреса или сети доверенных прокси через запятую; указывайте только контролируемые адреса |

Отдельные лимиты жёстче общего: `/register` и `/vault` — 5 в час, `/login` —
10 за 15 минут. Это защита от перебора паролей и от накрутки пустых хранилищ.
По умолчанию заголовок `X-Forwarded-For` игнорируется, чтобы клиент не мог
подменить адрес. Без настройки за Caddy все запросы учитываются как исходящие
от прокси и разделяют общий лимит. Чтобы учитывать посетителей отдельно, задайте
`TRUST_PROXY_CIDRS` только для контролируемых адресов прокси и настройте его на
удаление недоверенных входящих forwarded-заголовков. Не доверяйте общей сети с
неизвестными контейнерами. Лимиты хранятся в памяти каждого процесса и не
являются общими при запуске нескольких экземпляров.
