# Сервер THEDAD

Инструкция по запуску sync-сервера — от покупки статического IP до работающего
`https://sync.thedad.ru` с ежедневными бэкапами. Подходит и для домашней машины,
и для любого VPS: всё, что ниже раздела «Роутер», одинаково.

## Нужен ли он для релиза

**Для версии 1.0 — нет.** Приложение работает полностью без сервера:

| Что | Где живёт | Сервер нужен? |
|---|---|---|
| Сайт thedad.ru | GitHub Pages, ветка `gh-pages` публичного `thedad-releases` | Нет |
| Данные пользователя | В его браузере или на его компьютере | Нет |
| Резервная копия | Его собственный Google Диск, зашифрована на устройстве | Нет |
| Десктоп и расширение | Релизы `thedad-releases` | Нет |
| **Синхронизация между устройствами (Plus)** | **Этот сервер** | **Да** |

Plus в приложении скрыт флагом `VITE_FEATURE_PLUS`, пока нет биллинга. Сервер
можно поднять заранее, обкатать и включить Plus одной переменной, когда будете
готовы продавать.

## Дома или на VPS

| | Дома со статическим IP | VPS в России |
|---|---|---|
| Деньги | статический IP у провайдера, ~100–300 ₽/мес | ~300–600 ₽/мес за 2 ГБ RAM |
| Надёжность | зависит от света и интернета дома | дата-центр, резервное питание |
| 152-ФЗ (данные в РФ) | выполняется | выполняется, если хостер российский |
| Кто чинит железо | вы | хостер |

**Для старта домашний сервер — нормальный выбор**, и вот почему именно для этого
приложения: оно local-first. Если сервер лёг на час, пользователи не теряют
ничего — просто синхронизация подождёт. Поэтому сайт на домашнюю машину мы
**не** ставим (его недоступность отрезала бы новых пользователей), а синк — можно.
Когда пользователей станет много, та же папка переносится на VPS без изменений.

Бесплатные VPS из каталогов вроде freehosts.eu для этого не подходят: это в
основном контейнеры игровых панелей без root-доступа и Docker, без гарантий, и
машину могут забрать без предупреждения — вместе с данными пользователей.

### Про персональные данные

Сервер хранит e-mail и хеш пароля — это персональные данные. По 152-ФЗ база с
данными россиян должна находиться в России (домашний сервер или российский
VPS это закрывают), а до начала обработки нужно подать уведомление в
Роскомнадзор и опубликовать политику обработки ПДн. Содержимое хранилищ
зашифровано на устройстве пользователя и серверу не читаемо, но e-mail остаётся
e-mail'ом. Это не юридическая консультация — перед включением Plus стоит
показать схему юристу.

## Что понадобится

- **Машина.** Любой компьютер на x86-64 или ARM64: мини-ПК, старый ноутбук,
  Raspberry Pi 4/5 с 8 ГБ. Минимум 2 ГБ памяти и 20 ГБ на SSD. Raspberry Pi —
  только с SSD, не с microSD: карта памяти под базой данных умирает за месяцы.
- **Ubuntu Server 24.04 LTS** — скачать на ubuntu.com, записать на флешку
  через balenaEtcher или Rufus.
- **Статический IP** от провайдера.
- **Доступ к DNS** домена thedad.ru — там, где вы его покупали.
- **Желательно ИБП** — пропадание питания посреди записи в базу не опасно для
  Postgres, но лишние перезагрузки ни к чему.

## Шаг 1. Провайдер и статический IP

Позвоните или напишите провайдеру и спросите три вещи:

1. Можно ли подключить **статический (белый) IP** и сколько стоит.
2. **Не блокируются ли входящие порты 80 и 443.** Некоторые провайдеры закрывают
   их на домашних тарифах. Если закрыты — сервер дома не заработает, нужен VPS.
3. Разрешён ли на тарифе **собственный сервер** — чтобы не нарушить договор.

Запишите полученный IP — дальше он понадобится дважды.

## Шаг 2. Ubuntu

Поставьте Ubuntu Server 24.04 на машину. В установщике:

- имя пользователя — любое, например `thedad`;
- отметьте **Install OpenSSH server**;
- дополнительных пакетов (snaps) не ставьте — Docker поставит скрипт.

После установки узнайте локальный адрес машины (он понадобится для роутера):

```bash
ip -4 addr show | grep inet
```

Нужен адрес вида `192.168.x.x`.

## Шаг 3. Вход по ключу вместо пароля

На **своём компьютере** (Windows — в PowerShell):

```powershell
ssh-keygen -t ed25519
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh thedad@192.168.1.50 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

(`192.168.1.50` — замените на адрес машины из шага 2.)

Проверьте, что `ssh thedad@192.168.1.50` пускает без пароля. Потом **на сервере**
отключите вход по паролю:

```bash
sudo sed -i 's/^#\?PasswordAuthentication .*/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo systemctl restart ssh
```

## Шаг 4. Роутер

В настройках роутера:

1. **Закрепите за сервером постоянный локальный адрес** (раздел DHCP → резервирование
   адреса / static lease). Иначе после перезагрузки роутер выдаст ему другой, и
   проброс портов уйдёт в никуда.
2. **Пробросьте порты** (раздел «Переадресация портов», «Virtual Server», «NAT»):
   - внешний `80` → `192.168.1.50:80`
   - внешний `443` → `192.168.1.50:443`

**Порт SSH (22) наружу не пробрасывайте.** Управляйте сервером из домашней сети.
Если нужен доступ из поездки — поставьте WireGuard или Tailscale, а не открывайте
SSH всему интернету.

## Шаг 5. DNS

В панели управления доменом thedad.ru добавьте запись:

| Тип | Имя | Значение |
|---|---|---|
| A | `sync` | ваш статический IP |

Запись расходится от нескольких минут до пары часов. Проверка с любого компьютера:

```bash
nslookup sync.thedad.ru
```

Должен вернуться ваш статический IP.

## Шаг 6. Код на сервер

Репозиторий приватный, поэтому серверу нужен ключ **только на чтение** — не ваш
личный. На сервере:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/thedad_deploy -N ""
cat ~/.ssh/thedad_deploy.pub
```

Скопируйте вывод. На GitHub: репозиторий `planer` → Settings → **Deploy keys** →
Add deploy key → вставить, **галочку Allow write access не ставить**.

Снова на сервере:

```bash
cat >> ~/.ssh/config <<'EOF'
Host github.com
  IdentityFile ~/.ssh/thedad_deploy
EOF
git clone git@github.com:uyellowline/planer.git ~/planer
```

## Шаг 7. Установка

```bash
cd ~/planer
sudo deploy/server/scripts/install.sh
```

Скрипт ставит Docker, включает автоматические обновления безопасности,
закрывает все входящие порты кроме SSH, 80 и 443, создаёт `.env` со
сгенерированным паролем базы и включает ежедневный бэкап. Запускать повторно
безопасно.

Откройте `.env` и впишите две строки:

```bash
sudo nano deploy/server/.env
```

```
SYNC_DOMAIN=sync.thedad.ru
ACME_EMAIL=ваша@почта.ru
```

Сохранить — `Ctrl+O`, `Enter`, выйти — `Ctrl+X`.

> **Пароль базы — только латинские буквы и цифры.** Docker Compose трактует `$`
> в `.env` как переменную, а пароль вклеивается в адрес подключения, где `@`,
> `/`, `:` и `#` ломают разбор. Сгенерированный скрипт пароль этим правилам
> соответствует — трогать его не нужно.

## Шаг 8. Запуск

```bash
cd ~/planer/deploy/server
sudo docker compose up -d --build
sudo docker compose ps
```

Все три сервиса должны быть `Up`, `db` и `sync` — `(healthy)`. Первый запуск
занимает пару минут: Caddy получает сертификат Let's Encrypt.

**Проверяйте снаружи дома** — с телефона через мобильный интернет, не через
домашний Wi-Fi:

```
https://sync.thedad.ru/health
```

Ответ `{"ok":true}` — сервер работает. Изнутри домашней сети адрес может не
открыться, даже когда всё настроено верно: многие роутеры не умеют
«развернуть» запрос к собственному внешнему IP обратно внутрь (hairpin NAT).
Это не ошибка сервера.

## Шаг 9. Бэкапы вне дома

Ежедневный дамп уже идёт в `deploy/server/backups/` в 03:30. Но копия на том же
диске не спасёт от пожара, кражи или смерти самого диска. Отправьте её наружу —
например, на Яндекс Диск (остаётся в России).

**1. Подключите Яндекс Диск к rclone.** У сервера нет браузера, поэтому
авторизация в два приёма. На **своём компьютере** установите rclone
(rclone.org/downloads) и выполните:

```bash
rclone authorize "yandex"
```

Откроется браузер, войдите в Яндекс. В терминале появится токен в фигурных
скобках — скопируйте его целиком. На **сервере** (именно через `sudo`: бэкап
запускается от root и ищет настройки rclone у root):

```bash
sudo rclone config
```

`n` (новое) → имя `yadisk` → тип `yandex` → client_id и secret пустые → на вопрос
про auto config ответьте `n` → вставьте токен → подтвердите.

**2. Впишите в `.env`** (`sudo nano .env` — файл принадлежит root):

```
BACKUP_RCLONE_REMOTE=yadisk:thedad-backups
BACKUP_PASSPHRASE=длинная-фраза-которую-вы-сохранили-отдельно
```

Дамп шифруется этой фразой перед отправкой — Яндекс видит только шифр. **Храните
фразу не на сервере** (в менеджере паролей): если сервер пропадёт, без неё
копия бесполезна.

**3. Проверьте:**

```bash
sudo systemctl start thedad-backup.service
sudo journalctl -u thedad-backup -n 20 --no-pager
```

В конце должно быть «Удалённая копия отправлена», а на Яндекс Диске — файл в
папке `thedad-backups`.

**Необязательно — уведомление, если бэкап не прошёл.** Заведите бесплатную
проверку на healthchecks.io с периодом 1 день, адрес пинга впишите в
`BACKUP_PING_URL`. Если бэкап однажды не выполнится, придёт письмо. В пинге
нет никаких данных — только факт «бэкап прошёл».

## Шаг 10. Включить Plus в приложении

Когда сервер работает и биллинг готов — на GitHub, репозиторий `planer` →
Settings → Secrets and variables → Actions → **Variables**:

| Переменная | Значение |
|---|---|
| `VITE_SYNC_SERVER_URL` | `https://sync.thedad.ru` |
| `VITE_FEATURE_PLUS` | `1` |

Следующий push в `main` соберёт сайт и десктоп с включённой синхронизацией.

После публикации расширения в Chrome Web Store добавьте его адрес в
`ALLOWED_ORIGINS` в `.env` (ID — в адресе страницы расширения в магазине) и
перезапустите: `sudo docker compose up -d`.

## Обслуживание

Все команды — из `~/planer/deploy/server`, через `sudo`.

| Задача | Команда |
|---|---|
| Состояние | `docker compose ps` |
| Логи сервера | `docker compose logs -f sync` |
| Обновить до новой версии | `scripts/update.sh` |
| Сделать бэкап сейчас | `scripts/backup.sh` |
| Восстановить | `scripts/restore.sh backups/thedad-....sql.gz` |
| Список бэкапов | `ls -lh backups/` |
| Перезапустить | `docker compose restart` |

**Обновление** (`update.sh`) сначала делает бэкап с меткой `pre-update`, потом
забирает код, пересобирает и проверяет, что сервер отвечает. Если не отвечает —
покажет логи; база при этом не тронута.

**Восстановление** (`restore.sh`) спросит подтверждение словом ВОССТАНОВИТЬ,
сначала сохранит текущее состояние копией с меткой `pre-restore` — так
ошибочное восстановление можно откатить, — а потом заменит базу. Принимает и
обычные дампы, и зашифрованные `.gpg` с Яндекс Диска. Неверная фраза
расшифровки прерывает процесс до того, как база тронута.

Система обновляет пакеты безопасности сама. Раз в пару месяцев стоит зайти и
сделать `sudo apt upgrade` и `sudo reboot` — после перезагрузки всё поднимется
само.

## Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| `/health` не открывается с телефона | Проверьте по порядку: `nslookup sync.thedad.ru` возвращает ваш IP → проброс 80/443 в роутере → `docker compose ps` → `docker compose logs caddy` |
| Caddy пишет про сертификат / ACME | Порт 80 не доходит до сервера снаружи — Let's Encrypt проверяет домен через него. Проверьте проброс и что провайдер не режет 80 |
| Открывается из дома, но не с телефона | Провайдер блокирует входящие порты, или IP не статический и сменился |
| Открывается с телефона, но не из дома | Hairpin NAT — нормально, см. шаг 8 |
| `/health` отвечает 503 | Сервер жив, база недоступна: `docker compose logs db` |
| `/health` отвечает 502 | Не отвечает сам сервер: `docker compose logs sync` |
| Бэкап не уходит на Яндекс Диск | `sudo rclone lsd yadisk:` — если ошибка, токен устарел: повторите шаг 9.1 |
| Закончилось место | `docker system df`, `df -h`; старые образы: `docker image prune -a` |

## Что уже сделано для безопасности

- наружу открыты только 80 и 443; база и сам сервер — внутри сети Docker;
- HTTPS с автоматическим продлением, HSTS, запрет встраивания во фреймы;
- лимиты: 120 запросов в минуту с IP, вход — 10 попыток за 15 минут,
  регистрация и создание хранилища — 5 в час;
- CORS пускает только адреса из `ALLOWED_ORIGINS`;
- сервер в контейнере работает не от root;
- дампы на диске доступны только root, наружу уходят только зашифрованными;
- автоматические обновления безопасности системы.

## Что проверено

Весь стек поднимался локально в Docker и прогонялся по сценариям: HTTPS и
редирект с http, заголовки безопасности, регистрация, вход без учёта регистра
e-mail, запись и чтение хранилища, отказ по чужому токену, срабатывание лимита
на десятой попытке входа, CORS для сайта, десктопа и отказ чужому сайту,
бэкап, «авария» с удалением всех данных и восстановление, восстановление из
зашифрованной копии, отказ при неверной фразе без касания базы, корректная
остановка за секунду, честный 503 и самовосстановление при падении базы.
